## 1. 机械臂本体结构复刻与零件体系建立

**完成时间：2026-10-14**

### 1.1 功能描述

本板块对应机器人的**"结构本体"功能**：把一套开源机械臂的 14 个 STL 零件，从"一堆无名几何体"转化为"有明确装配语义、可核对、可复现的零件体系"，为后续打印、装配与运动控制提供唯一可信的数据源。

具体要解决三个问题：

1. **每个零件叫什么、装在哪**——建立中英对照命名与装配位置；
2. **每个零件上的孔位在哪里、多大、是通孔还是沉孔**——这是所有关节能否装上的前提；
3. **结构上是否存在"长得一样但其实是同一功能的不同实现"的零件**——决定到底该打哪几个。

### 1.2 开发历程

#### 1.2.1 起点：只有 14 个 STL 和一张实物照片

接手这个模块时，手上只有两样东西：源仓库 `meshes/` 目录下的 14 个 STL，以及一张整机实物照片。没有任何装配图、没有 BOM、没有零件说明。英文文件名（`base_plate`、`forward_drive_arm`、`triangular_link`…）对不上照片里的任何具体位置——**第一个卡点不是设计，而是"看不懂"**。

我的处理顺序是：先做**命名与定位**，再做**孔位量化**。理由很直接——命名错了，后面所有讨论都会错位；孔位不确定，画图和采购就无从谈起。

命名上采取了"**中文功能名 + 保留原始英文名**"的双轨制，例如"水平臂（horizontal_arm）"。这样做的好处是：中文名便于队内沟通，英文名保证任何时候都能回溯到源文件，不会因为翻译而丢失可追溯性。

#### 1.2.2 第一次尝试及其不足

最初的孔位识别是"目视 + 包围盒尺寸粗配"：看外形尺寸接近就认为是同一类零件。很快发现问题：

- **长条状零件的包围盒会互相"撞车"**——`horizontal_arm`（127.5×15×8）和 `link`（92×12×5）在某个朝向下包围盒比例接近，肉眼容易误判成"同一根杆"；
- **包围盒对"孔"完全无感**——两个零件外形再像，孔位不同就是不能互换；
- 更关键的是，**仅靠肉眼看渲染图，无法排除"某个零件其实是另一个零件拆开后的组合"**。

这一步的失败让我明确了一件事：**必须把"像不像"变成可计算的量**，否则讨论无法收敛。

#### 1.2.3 方法重构：全朝向刚体比对 + 体素 IoU

于是把问题形式化为几何比对问题，设计了一套两两比对流程：

1. **有限姿态枚举**：对每一对零件，枚举 24 种正交朝向及其镜像（共 48 种候选姿态）。这不覆盖任意连续旋转，镜像也不属于保持手性的刚体旋转；因此只能作为候选对齐筛选，不能单独证明零件可互换；
2. **表面采样**：每个零件均匀采样 15~20 万点，避免顶点密度不均带来的偏差；
3. **体素化**：以 1 mm 体素栅格、中心对齐后计算交并比（IoU）；
4. **绝对尺寸前置筛选**：先要求"尺寸差 < 1 mm 且体积差 < 8%"，不满足直接淘汰，避免细长条在某个姿态下"碰巧高度重合"造成的假阳性。

对 14 个零件共跑了 **91 组两两比对**。这个流程的价值不只是给出了一个"相似度排名"，而是**把"能不能互换"从主观判断变成了可复现的证据链**——这是我认为本板块最有意义的方法论转变。

#### 1.2.4 关键结论：底盘其实是"一体版"与"分体版"的二选一

比对中最重要的一处发现，是 `base_plate` 与 `plate + round_plate` 的关系。它们的相似度高得反常，但又不是简单复制。为确认，我做了三重独立验证：

| 验证维度  | 数据                                                                                       | 判定             |
| ----- | ---------------------------------------------------------------------------------------- | -------------- |
| 体积守恒  | `plate` 25300 mm³ + `round_plate`（Ø72×4.5）18322 mm³ = **43621**，`base_plate` = **43625** | 误差 **0.01%**   |
| 高度差   | 57.1 − 52.6 = **4.50 mm**，恰为圆盘厚度                                                         | 完全吻合           |
| 逐层截面积 | 塔楼部分最优偏移 0.03 mm，**中位误差 0.38%**                                                          | 同一几何模型         |
| 孔位对接  | `plate` 底部 2×Φ3.4（孔距 28 mm）↔ `round_plate` 沉头孔 Φ6.1/Φ3.4（孔距 28 mm）                       | 两颗 M3 沉头螺钉即可连接 |

**结论：二者是同一结构的"一体打印版"与"分体拼装版"，只能二选一，绝不能三个都打。** 这一点如果不查清，直接后果是白打一个零件、多耗 40 g 材料，并在装配时发现装不进去。

这里也体现了一个设计判断：**一体版**少两颗螺丝、刚性更好、少一道装配工序；**分体版**的转盘可单独更换、大平面更不容易翘边。对比赛场景（需要反复拆装调试）我倾向保留分体路线作为备选，但主方案走一体版以减少装配误差累积。

#### 1.2.5 孔位复核：双方法交叉，只信"两种方法都同意"的孔

孔位识别用两套互相独立的算法交叉验证：

- **主方法**：识别圆柱侧面片元，最小二乘拟合圆心与半径；
- **辅方法**：沿孔轴向切 5 层截面，用截面轮廓的圆度（> 0.75）筛出圆孔。

两者一致 → 标为高可信；只有一种检出 → 标记存疑，必须回头深挖。随后对 4 个存疑项做了专项复核：

| 存疑项                               | 复核方式            | 结论              |
| --------------------------------- | --------------- | --------------- |
| `pi_camera` 是否缺角孔                 | 调整截面层位重扫        | ✅ 4×Φ2.1 四角孔齐全  |
| `round_plate` 中心 Φ2.0 是否为真        | 多层连续扫描          | ✅ 真实中心小孔（非舵机轴孔） |
| `base_plate`/`plate` 的 Φ4.2 是否带沉孔 | 40 层密扫，检查直径是否变化 | ✅ 全程恒径，普通通孔，无沉孔 |
| `forward_drive_arm` 的 Φ16.9 是否为开口 | 30 层密扫，全深度恒径恒心  | ✅ 确认为贯穿圆孔       |

这一步的方法论收获是：**"检测到孔"和"这个孔真的存在"是两件事**。单层截面很容易把圆角、倒角、开口误判成孔；只有"多层恒定直径 + 两种方法一致"才敢写进清单。

#### 1.2.6 本板块产出

- 14 件零件的**中英对照命名表**与实物位置标注；
- 全机**约 60 个通圆孔**的坐标/孔径/置信度清单（其中 24 个高可信）；
- `base_plate ≡ plate + round_plate` 的**二选一判定**（三重证据）；
- 4 个存疑孔位的**专项结案报告**。

> **反思**：这一阶段最大的教训是"不要用低维特征去回答高维问题"。包围盒是粗略的外形摘要，不能保留孔位和内部结构。体素 IoU 可增加几何比较信息，但结果仍受姿态、对齐和体素精度影响；本次仓库尚缺模型与脚本，暂不能由读者复现。

## 2. 零件互换性判别与打印数量核定

**完成时间：2026-10-15**

### 2.1 功能描述

本板块对应机器人的**"可制造性"功能**：在正式采购耗材与开机打印之前，回答三个直接影响成本与装配的问题：

1. 哪些零件可以**互相替代**（打一个就够，不必都打）？
2. 哪些零件**看起来像但不能互换**（差一点就会装不上）？
3. 每个零件**到底打印几个**（是否存在需要重复打印的对称件）？

### 2.2 开发历程

#### 2.2.1 为什么值得单独做一遍

在 10-14 已有一份孔位清单的前提下，我仍然决定单独做互换性判别，理由是**成本结构**：一次错误的"少打"会让整机停在半成品状态等快递；一次错误的"多打"则直接浪费 40 g 以上材料和 2 小时机时。对比赛备赛期而言，**时间比材料更贵**，所以宁可花 2 小时做甄别，也不赌一次。

#### 2.2.2 三步筛选法

为了避免"凭感觉认定像"的错误，设定了递进式筛选：

1. **绝对尺寸筛选**：尺寸差 < 1 mm 且体积差 < 8%（宁可严，不可松）；
2. **姿态枚举比对**：24 朝向 × 镜像，计算 IoU；
3. **功能孔核对**：即使外形吻合，只要**功能孔数量或位置不同**，一律判定不可互换。

第 3 条是这次判别中最关键的一条，因为它是**唯一能推翻"外形相似"的证据类型**。

#### 2.2.3 左右指片：镜像孪生，但不能互换

`left_finger` 与 `right_finger` 的比对结果非常典型：

- 外形尺寸差仅 **0.48 mm**，体积差 5.1%；
- **镜像 IoU 0.614，纯转置仅 0.367** → 确认是镜像关系而非复制关系；
- 但功能孔完全不同：`left_finger` 有 **3 个** Φ3.2~3.4 孔（X = 42.8 / 47.5 / 52.2，两侧深约 2.3 mm）；`right_finger` 只有 **1 个** Φ3.2 贯穿孔（X = 47.5）。

为排除"检测漏检"的可能，又用 Z 向 24 层 + Y 向 20 层做了密扫，结论不变：右指片确实只有 1 个孔。

**判定：镜像孪生但不可互换，必须左右各打 1 个。** 如果按"一片打两个"的思路去做，右侧会缺失两侧安装孔，夹爪无法固定。

#### 2.2.4 三方对照：源文件 / 清单 / 实物，确认无遗漏

为避免"清单本身漏件"，做了三方交叉：

- **源文件侧**：用仓库文件树 API 全量列举，`meshes/` 下**恰好 14 个 STL**，与清单逐一对应，不存在第 15 个网格；
- **清单侧**：14 件；
- **实物侧**：14 件中 13 件可在照片中定位（5 件完全可见、5 件被遮挡但可解释、3 件角度难辨但结构位置明确），`pi_camera` 属**可选配件且实物未安装**。

**结论：14 = 14 = 14（其中 1 件为可选未装），无遗漏、无多余。**

#### 2.2.5 打印数量核定

逐件核定后得到一个反直觉但重要的结论：**没有任何一个零件需要打印 2 个以上**。原因是所有"成对需求"在源文件中都以左右两个独立文件提供了，而不是让同一个文件打两遍。

| 类别      | 零件                                                                       | 数量       |
| ------- | ------------------------------------------------------------------------ | -------- |
| 底座/回转   | basement                                                                 | 1        |
| 底盘（二选一） | base_plate ×1 **或** plate ×1 + round_plate ×1                            | 1 / 2    |
| 臂与连杆    | forward_drive_arm、horizontal_arm、link、triangular_link、vertical_drive_arm | 各 1      |
| 夹爪      | claw_support ×1、left_finger ×1、right_finger ×1                           | 3        |
| 附件      | servo_plate ×1、pi_camera（可选）                                             | 1（+1 可选） |

**合计**：路线 A（一体底盘）**11 件**；路线 B（分体底盘）**12 件**；均不含可选摄像头支架。

#### 2.2.6 本板块产出

- 可替代关系 1 组（底盘），镜像不可互换关系 1 组（左右指片），其余 87 组全部排除；
- 三方对照表（源文件 / 清单 / 实物）；
- 打印数量表与两条装配路线的总件数。

> **反思**：这一步真正教会我的是"**相似不等于可替代**"。工程上判断替代关系，不能只看几何相似度，必须回到**功能定义**——孔是干什么用的、装什么、受什么力。这也是我后来做舵机选型时反复使用的一条原则。

## 3. 驱动与回转支撑方案选型：舵机、钢珠与轴承

**完成时间：2026-10-15**

### 3.1 功能描述

本板块对应机器人的**"驱动与承载"功能**：为 4 个自由度（底座回转、肩、肘、夹爪）选定舵机型号，并判断原版设计中"25 颗 Ø6 钢珠 + 1 个 606ZZ 轴承"这套回转支撑方案在**本方案上是否必要**。

这两个问题直接决定采购清单与整机负载能力，是"能不能动起来"和"能动多快、能拿多重"的分水岭。

### 3.2 开发历程

#### 3.2.1 先厘清：原版与本方案不是同一台机器

原版 EEZYbotARM MK2 的官方 BOM 是 **3× MG946/MG955 + 1× SG90**，并明确写了 "the vertical axis supported by spheres"——即**回转平台由钢珠环 + 606ZZ 轴承承压减摩**。

而我手上这套（下称"方案 2"）的文件夹命名就是 `arduinobot_SG90`，实物照片里可见**蓝色 SG90**，且这套 14 件模型中**不含原版的打印齿轮（`gearservo`）与齿圈（`gearmast`）**。也就是说，原版"齿轮驱动滚珠转盘"的传动链在这里被整体简化掉了。

**这个差异不是细节，而是选型的出发点**：原版用大舵机 + 滚珠环，是因为它要扛大负载；本方案是全小舵机轻载机，两套设计的力学前提根本不同。因此不能"照着原版 BOM 抄"，必须重新算一遍。

#### 3.2.2 舵机选型对比

把所有候选放在同一张表里比较（数据取自 TowerPro 官方与各分销商规格书）：

| 项目       | MG946R        | MG955         | MG995                | MG996R         | SG90           |
| -------- | ------------- | ------------- | -------------------- | -------------- | -------------- |
| 类型       | 数字            | 模拟（旧款）        | 多为模拟                 | 数字             | 模拟             |
| 堵转扭矩 @6V | **13 kg·cm**  | ~10–13（克隆差异大） | 10–13（标 13/15KG 多虚标） | 11–13 kg·cm    | **1.8 kg·cm**  |
| 速度 @6V   | 0.17 s/60°    | ~0.17–0.20    | 0.16–0.20            | **0.14 s/60°** | 0.12 s/60°（空载） |
| 工作电压     | 4.8–**6.6V**  | 4.8–6V        | 4.8–**7.2V**         | 4.8–**7.2V**   | 4.8–6V         |
| 齿轮       | 金属（6061-T6 铝） | 金属            | 金属（廉价版半金属）           | 金属             | **塑料**         |
| 轴承       | 双滚珠           | 单/无           | 部分带                  | 双滚珠            | 无              |
| 重量       | 55 g          | ~55 g         | ~55 g                | ~55 g          | **9 g**        |
| 旋转角      | 180°          | 180°          | 180° **或 360°（坑）**   | 180°           | 180°           |

选型时我重点核对了三个容易被忽略的点：

1. **数字 vs 模拟**：数字舵机通常具有不同的控制响应特性，但不能仅凭“数字”标签保证死区小或不抖；仍需看实际型号与测试。机械臂关节需要稳定停在某个角度，模拟舵机的抖动会直接放大成末端位移，所以**关节优先数字**。
2. **电压上限**：MG946R 只能到 6.6V，若用 2S 锂电（满电 8.4V / 标称 7.4V）直驱会**超压**；即使按原表 7.2V 上限考虑，2S 电池标称 7.4V、满电 8.4V 仍然超过该值，不能据此直接供电；实际型号规格须逐件核对，并使用匹配的稳压供电。原表各商品规格尚未在本次整理中独立复核。
3. **360° 连续旋转版本的陷阱**：市面部分 MG995/996 是**连续旋转版**，失去角度定位能力，装到关节上会"一直转"。采购时必须确认是 **180° 标准位置舵机**。同理，**SG90 的 360° 版本绝不能用于关节**——关节需要位置闭环，连续旋转舵机只能控速控向。

#### 3.2.3 力矩预算：为什么"全 SG90"只能做轻载演示

这是本板块最重要的一次定量分析。已知臂长（第 4 板块实测）：大臂 115 mm、小臂 80 mm，夹爪前伸约 35 mm，即**肩部到末端约 230 mm**。

按简化静力矩估算（忽略动载与摩擦，取保守值）：

| 关节       | 需承担的远端质量（估） | 质心力臂    | 需求力矩           | SG90（1.8） | MG996R（13） |
| -------- | ----------- | ------- | -------------- | --------- | ---------- |
| 底座回转     | 整机约 450 g   | 摩擦主导    | —              | 勉强        | 充裕         |
| 肩（抬大臂）   | 约 150 g     | ~150 mm | **≈2.3 kg·cm** | **不足**    | 充裕         |
| 肘（抬小臂+爪） | 约 90 g      | ~90 mm  | ≈0.8 kg·cm     | 临界        | 充裕         |
| 夹爪       | 指尖轻载        | —       | 很小             | 可用        | 可用         |

结论很清楚：**全 SG90 时肩关节在空载下就已接近/超过额定扭矩**，实际表现会是"抬得慢、抬不高、末端一挂负载就掉"。它能完成的只是**空载演示与轻物抓取**；若比赛任务要求抓取 100 g 以上或做快速往复，**需要重新评估肩/肘驱动及结构承载，并以实测确定升级型号**（若以 13 kg·cm 计算，230 mm 力臂下约 560 g 仅为忽略臂重、动载与安全余量的静态换算，不能作为额定抓取负载）。

这一分析也解释了为什么"方案 2 全 SG90"的实物看起来能用：**结构件通用，但力矩余量几乎为零**——这是设计取舍，不是缺陷。我的处理是：结构按 14 件统一打印（不改模型），电装先按 SG90 做功能验证，同时预留大舵机位的安装空间与独立 5V/6V 供电。

#### 3.2.4 钢珠与轴承：用"找不到结构"来证伪

原版需要 25 颗 Ø6 钢珠 + 1 个 606ZZ（d6/D17/B6）。判断本方案是否需要，我没有靠"看照片觉得没有"，而是**去找它必须存在的结构证据**——如果没有承载结构，那么这两样东西就是多余的。

检验设计：如果要用轴承，`basement` 上必须有一个 **Ø17 圆柱窝（深约 6 mm）**；如果要用钢珠，`basement` 顶面必须有一圈**宽 ≥6 mm 的环形滚道**。

实测结果：

| 检查项       | 期望特征                  | 实测                                                                                    |
| --------- | --------------------- | ------------------------------------------------------------------------------------- |
| 606ZZ 轴承座 | Ø17 圆柱窝，深约 6 mm       | ❌ 未找到。`basement` 上只有 3×Φ4.5 固定孔，中心是 Ø11.6 通道（M6 过孔）；Ø16.6 那个孔偏心 36 mm，是舵机输出凸台过孔，不是轴承座 |
| 钢珠滚道      | 环形沟槽，宽 ≥6 mm、深 1~2 mm | ❌ 未找到。射线高度图显示顶面是一道**平整环形台面**（半径 28~30 mm 处最高），中间敞口，无独立环槽                              |


补充佐证：实物照片中黑色转盘**直接压在底座盒上，看不到滚珠环应有的缝隙**；且 14 件模型里不含原版齿轮传动件，从侧面支持"简化掉滚珠转盘"的判断。

**历史方案判断：现有几何未体现原版钢珠/轴承安装结构，因此暂不照搬原版采购清单。** 转盘滑动支撑的摩擦、磨损和承载能力仍需实物验证；“没有安装座”不能单独证明任何负载下都无需支承。

同时给队里留了一个 10 秒自检法：拿起打好的 `basement`，看中心孔周围**有一圈明显凹槽** → 是原版带滚珠环结构，需备 25 颗钢珠 + 1 个 606ZZ；**是一圈平整面** → 不需要买。

#### 3.2.5 本板块产出

- 舵机选型对比表 + 力矩预算表（明确了"全 SG90 = 轻载"的定量边界）；
- 钢珠/轴承"不需要"的实证结论与 10 秒自检法；
- 采购红线 3 条：**关节只用 180° 位置舵机**、**MG946R 不可接 2S 直驱**、**舵机供电需按实际峰值电流设计**（原文电流为估计，实际需核对；不要把主控板的小电流电源引脚当作大舵机动力供电）。

> **反思**：这一板块让我第一次真正体会到"**选型不是选参数最大的，而是选匹配工况的**"。如果不是先算力矩，很容易陷入"原版用大舵机所以我也要用大舵机"的盲目模仿；反过来，如果只图便宜全上 SG90 又不承认它只能轻载，比赛现场就会翻车。把边界写清楚，比给出一个"看起来很强"的方案更有价值。

## 4. 机械臂尺度标定：臂长与连杆基准

**完成时间：2026-10-16**

### 4.1 功能描述

本板块对应机器人的**"尺度基准"功能**：从 STL 中量出每条臂的**有效长度（转轴孔心距）**，为后续三件事提供基准数据：

1. **正/逆运动学**——末端位姿计算需要准确的连杆长度；
2. **舵机限位标定**——角度范围必须结合臂长与结构干涉来确定；
3. **负载与配重估算**——力矩预算的力臂直接来自这里。

### 4.2 开发历程

#### 4.2.1 为什么不能"看包围盒就当臂长"

包围盒给的是**外轮廓最大跨度**，而运动学需要的是**两个转轴的中心距**。两者差异可能达到十几毫米——对 230 mm 的臂来说，10 mm 误差足以让末端定位偏出几厘米。所以必须量孔，不能量外形。

#### 4.2.2 三次方法迭代

| 迭代    | 方法                        | 结果           | 问题                                                                     |
| ----- | ------------------------- | ------------ | ---------------------------------------------------------------------- |
| 第 1 次 | 圆柱面最小二乘拟合（复用孔位清单的算法）      | 扁平臂件上一个孔都没检出 | 臂件是薄板结构，圆柱侧面片元被大量平面片元「淹没」，聚类失败                                         |
| 第 2 次 | 截面多边形内环识别                 | 仍然 0 个孔      | `section()` 返回的是 **Path3D**，没有 `polygons_full` 属性；必须先投影到 2D            |
| 第 3 次 | `to_2D()` 投影 + 内环 + 3D 聚类 | ✅ 全部检出       | 新版 trimesh 的 `to_2D()` 返回**元组** `(Path2D, to_3D 矩阵)`，必须取 `[0]` 才能访问多边形 |

第 3 次的方法链条是：沿孔轴多层切片（31 层）→ 取截面多边形的**内环**（内环即孔洞）→ 用返回的 3D 变换矩阵把孔心换算回**模型世界坐标** → 用 KD-Tree + 并查集做 3 mm 聚类去重 → 剔除只在少数切片出现的噪声。


这里有两个必须记录的经验：**一是"检测失败"往往不是算法错，而是数据结构理解错**（Path3D vs Path2D）；**二是只有在世界坐标下聚类，才能避免同一孔在不同切片上漂移成两个假孔**——早期版本就出现过相距 2.7 mm 的"重复孔"，正是这个原因。

#### 4.2.3 实测结果

| 零件                        | 外形（mm）           | 有效孔心距        | 说明                                              |
| ------------------------- | ---------------- | ------------ | ----------------------------------------------- |
| **horizontal_arm**（大臂）    | 127.5 × 15 × 8   | **115.0 mm** | 3 个 Φ4~4.2 通孔：7.6 / 42.6 / 122.6；分段 35.0 + 80.0 |
| **forward_drive_arm**（小臂） | 92.5 × 29 × 15   | **80.0 mm**  | 两端 Y 向 Φ4.2 销孔；中部 1×Φ16.9 + 2×Φ11.7             |
| link（连杆）                  | 92.0 × 12 × 5    | **80.0 mm**  | 两端 Φ4 通孔                                        |
| vertical_drive_arm        | 46.5 × 13 × 7.5  | **35.1 mm**  | 两端 Φ4 孔，另含 Φ11.8/Φ11.1 舵机盘窝                     |
| claw_support              | 54.0 × 25 × 38.2 | —            | 夹爪座，非臂段                                         |

#### 4.2.4 关键发现：80 mm 是平行四连杆的特征杆长

把数据放在一起看，会发现一个非常整齐的规律：

- 小臂两销孔距 = **80.0 mm**
- 连杆两孔距 = **80.0 mm**
- 大臂中后段（42.6 → 122.6）= **80.0 mm**

**三处 80 mm 完全一致，这不是巧合，而是平行四连杆（parallelogram linkage）的必然结果**：平行四边形对边等长，才能保证末端夹爪在抬升过程中保持姿态不变。这也解释了为什么这台机械臂的夹爪能"一直保持水平"——它不是靠软件补偿，而是**结构本身的自约束**。

由此可以确定整机的几何基准：

- **大臂有效长度 ≈ 115 mm**（肩 → 肘）
- **小臂有效长度 ≈ 80 mm**（肘 → 腕）
- **理论最大水平伸展 ≈ 115 + 80 = 195 mm**（再加夹爪前伸约 35 mm，末端可达约 230 mm）

#### 4.2.5 这个数据后面怎么用

- **运动学**：115 / 80 直接作为 DH 参数里的连杆长度，末端位置可由两关节角解析求得；
- **限位**：结合大臂 115 mm 的扫掠半径判断与底座/立板的干涉边界，避免舵机顶死导致堵转烧毁；
- **力矩**：第 3 板块的力臂计算正是基于这两个值，所以"全 SG90 只能轻载"的结论是可追溯的，不是拍脑袋。

> **反思**：这次迭代让我认识到"**测量工具本身也需要被验证**"。前两次失败时，我一度怀疑模型有问题；实际上模型完好（水密、34824 面），问题在于我假设了 API 的返回类型。工程上遇到"数据全为空"时，第一步应该验证**取数链路**，而不是怀疑被测对象。

## 5. 底盘大体积分件打印与拼接结构设计

**完成时间：2026-10-17**

### 5.1 功能描述

本板块对应机器人的**"承载底盘"功能**：机械车底盘需要在 Fusion 360 中完成结构设计，并解决"**整体尺寸超出打印机成型体积、无法一次打印**"的制造约束，最终输出可打印、可装配、承力可靠的分件方案。

底盘结构特征：主体为深腔盆体（电池/电控仓），前部接带加强筋的斜面甲板，甲板上布置了多组螺钉孔与一个矩形开窗。整体呈"盆体 + 甲板"的 L 形轮廓。

### 5.2 开发历程

#### 5.2.1 约束识别

问题不是"模型画错了"，而是**制造边界**：整件最大尺寸超过热床可用范围。这类问题的处理有 4 条路线，我先做了一次横向比较，而不是直接动手切：

| 路线              | 做法           | 优点              | 代价                   | 判定       |
| --------------- | ------------ | --------------- | -------------------- | -------- |
| A 整体缩放          | 按比例缩小到能装下    | 一步到位            | 孔位、舵机位、壁厚全部失真，装配件装不上 | ❌ 否决     |
| B 换设备/外协        | 找大尺寸机器或外包    | 不改设计            | 成本与周期不可控，比赛期不可行      | ❌ 否决     |
| C **分件打印 + 拼接** | 切成 2 件，打印后拼回 | 保留全部尺寸精度，材料利用率高 | 需要设计拼接结构、多一道装配       | ✅ **采用** |
| D 改结构拓扑         | 重画成可拆的板拼结构   | 最彻底             | 工作量大，且偏离原有设计意图       | ⏸ 备选     |

选择 C 的核心逻辑：**比赛阶段最不能牺牲的是接口精度**（舵机位、螺钉孔位），而分件是唯一"不改接口、只改制造方式"的方案。

#### 5.2.2 Fusion 360 拆分实体：正确顺序是"先加连接特征，再切"

操作链（这是踩过坑之后确定的顺序）：

1. **构造切割面**：`构造(Construct)` → `偏移平面(Offset Plane)`，选基准面并输入偏移量，把平面推到预设切线位置；
2. **先加连接特征**：在切线两侧预先做出螺钉孔 / 凸台 / 凹槽；
3. **拆分**：`实体(Solid)` → `修改(Modify)` → **`拆分实体(Split Body)`**，*Body to Split* 选底盘，*Splitting Tool* 选构造平面 → 确定；
4. 浏览器中出现 **Body1 / Body2** 两个实体；
5. **分别导出**：右键 → `另存为网格(Save as Mesh)` → STL，分两次切片。

**为什么必须"先加特征再切"**：连接孔如果穿过切割面，先切再分别打孔就必须靠手动测量对位，两次建模的坐标系一旦有偏差，拼装就会错位 1~2 mm；而先打孔再切，切面会把同一个孔"共享"给两个实体，**拼回去天然同心**。这是整个流程里最关键的一条经验。

#### 5.2.3 拼接面结构：三种方案的对比

分件之后真正决定成败的不是"切得准不准"，而是"拼得牢不牢"。对比了三种截面做法：

| 方案                 | 结构                     | 强度                | 对齐精度     | 可拆性   | 适用           |
| ------------------ | ---------------------- | ----------------- | -------- | ----- | ------------ |
| ① 平切 + 定位销 + 胶     | 平面贴合，2~4 个 Φ3 销孔       | 中（依赖胶层）           | 高（销定位）   | ❌ 不可拆 | 轻载、非承力外壳     |
| ② **搭接台阶 + M3 螺钉** | 一侧凸台、一侧凹槽，搭接区穿 M3 + 螺母 | **高**（机械紧固 + 面接触） | 高（台阶自定位） | ✅ 可拆  | **承力底盘（采用）** |
| ③ 凸台凹槽插接 + 胶/螺钉    | 竖直方向对插                 | 中高                | 最高（治具级）  | 半可拆   | 需要反复对位的场合    |

最终选 **② 搭接台阶 + M3 螺钉**，理由有三：

1. **底盘是承力件**——要承受电池重量、电机振动与碰撞冲击，纯胶接在长期振动下会疲劳开裂；
2. **比赛需要反复拆装**——调试阶段要频繁打开电池仓，可拆卸是硬需求；
3. **台阶本身提供自定位**——即使螺钉还没拧紧，两件也不会相对错位，装配容错高。

同时做了两条补充设计：搭接区宽度取 **≥8 mm**（保证至少两排螺钉的排布空间）；切面**避开原有螺钉孔和加强筋**——加强筋被切断会形成应力集中点，后续容易从切缝起裂。

#### 5.2.4 打印方向：切面必须竖直

这是分件方案里第二个容易翻车的点。原则是：**本方案优先考虑竖直切割面**，这样两个零件都能"开口朝上、大平面贴床"平放打印，**目标为减少支撑，实际需按零件悬垂与切片预览确认**，且层间受力方向与主要载荷方向错开。

反过来，如果切面取水平面（横切成上下两半），下半件会变成一个"碗"，必须加大量支撑，且拼接面朝下会贴床被压出"象腿"，拼装时出现缝隙。

另外注意：**拼接面不要直接贴热床**。首层被压扁、边缘外扩，会导致两个面贴合不严，出现可见缝隙。

#### 5.2.5 快速验证路径

如果只是想先验证"切成两件后能不能装"，不必回 Fusion 改模型——直接在切片软件里切：

- **Bambu Studio / OrcaSlicer**：选中模型 → `Cut` → 平面切割，可勾选**自动生成定位销（dowels/plugs）**；
- **PrusaSlicer**：`Cut` 功能同样支持添加 dowels；
- 优点是 5 分钟出结果、销孔自动对齐；缺点是无法做台阶与螺孔，只能验证几何，不能替代正式方案。

我的做法是：**用切片软件快速验证切线位置是否合理（有没有切到孔、切完是否都能平放），确认后再回 Fusion 正式建模拼接结构**。这样避免在 Fusion 里反复试错，节省大量时间。

#### 5.2.6 本板块产出与判据

- 拆分流程 SOP（偏移平面 → 加特征 → Split Body → Save as Mesh）；
- 拼接结构选型结论（搭接台阶 + M3，搭接宽 ≥8 mm）；
- 切线选择判据 4 条：**避开孔位**、**避开加强筋**、**切面竖直可平放**、**不贴热床**；
- 一条快速验证路径（切片软件 Cut + 自动销钉）。

> **反思**：这个板块让我理解了"**制造约束会反向塑造设计**"。原本我以为 3D 打印是"画什么就能打什么"，实际上成型体积、层间强度、支撑代价都会反过来要求模型做妥协。分件不是"退而求其次"，而是一种**主动的设计手段**——把不可制造的整件，转化为可制造、可装配、可维修的组件。
